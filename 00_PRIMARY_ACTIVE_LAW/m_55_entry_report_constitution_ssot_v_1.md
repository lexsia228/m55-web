## 2. M55の心（Hard Freeze）

### 2-1. 存在目的
M55は、人の中にすでにある資質・傾向・偏りを見取り図として可視化し、本人が自分を誤解し続けないための自己観測システムである。

### 2-2. M55が売るもの

1. 見えなかった自分に、輪郭を。  
2. 否定していた自分に、意味を。

- 理解を売るのであって、恐怖を売らない

### 2-4. 商品の一文定義
M55 Entry Report は、無料で見えたあなたの輪郭を、8章の構造で意味と使い方まで整理し直し、自分を誤解し続けないために手元へ残す所有版である。

- M55は何か
- 何が見えるようになるか
- ¥1,000で何が深まるか

### 3-2. Homeの主役
Homeの公開主役は Entry Report である。

### 3-3. Home上部の題名ルール
Home Hero では **題名を必ず表示する**。

つまり、**意味上は一体、表示上は二段** で固定する。  
一行結合見出しにはしない。

- `M55` = 何のプロダクトか

## 4. ビジュアル憲法（Hard Freeze）

### 4-1. ビジュアルの役割
ビジュアルは神秘演出ではなく理解補助である。  
図は証明ではなく解釈の補助。  
イラストはかわいい飾りではなく体験の感情翻訳である。

### 4-2. M55のビジュアル人格
- quiet
- premium
- analytical
- editorial
- layered
- readable
- precise

### 4-3. 競合や外部メモから借りるもの
- 一貫したタイポ
- 一貫した下線
- 一貫した図形言語
- 一貫したイラストの人格
- 結果の実体が数秒でわかる構成
- 情報の引き算
- 英字ラベルや数値まわりでの限定的な monospace 使用
- ごく薄い grid / blueprint 的補助線

### 4-4. 借りないもの
- 派手な媒体トーン
- 占いメディア的なバナー密度
- 大袈裟な神秘演出
- 数字の誇張
- testimonial の大量顔出し
- 黒 + ネオンのサイバー世界観の主軸化
- 擬似科学・神秘寄りの loading 文言
- 選民感のある世界観命名

### 4-5. canonical image assets
- `public/home/hero-tech-map.webp` = Hero main visual
- `public/home/card-how-to-see.webp` = 見方を知るカード
- `public/home/card-qualities.webp` = 10通りの資質カード

### 4-6. Home Hero visual 実装固定
- Hero画像は full-bleed 背景にしない
- 既存の横長カード枠内に `object-fit: cover` で配置する
- 底面に tech map、上層に薄い白オーバーレイ、その上に「白いレポート束 / 見取り図」モチーフを重ねる
- 目的は「精密な解析データを、個人向けレポートとして整理して届ける」体験の視覚化である

### 4-7. 図形・色・下線の固定ルール
- 下線は装飾ではなく意味の導線として使う
- 既存の5色は意味色として昇格させる
- 色は新規追加で増やさず、既存資産を統一運用する
- 見出し下線 / タグ / アイコン / カードアクセント / 図版パーツに反復利用する

### 4-8. タイポの固定ルール
- 見出しは太く、本文は軽く
- 日本語は読みやすさ優先
- 余白で高級感を作る
- コントラスト不足を放置しない
- CTAだけは背景より一段強く見せる
- 英字ラベル / 数値 / micro UI では、限定的に monospace を使ってよい
- ただし本文全体を monospace 化しない
- monospace は分析補助の記号であり、世界観の主役ではない

### 4-9. イラストの固定ルール
- 人物は主役にしすぎない
- だが完全無機質にもしない
- editorial portrait / quiet portrait / silhouette 的な使い方を推奨
- 目的は感情移入の入口づくりであり、媒体化ではない

### 4-10. Blurの固定ルール
Blurは「罰」ではなく「境界線」である。  
ここから先は owned structure があることを示すために使う。  
見出しは読めるが本文は全部は読めない、程度に抑える。

### 4-11. Home上の主要visual数の上限
major visual は3つを推奨、4つを上限とする。

- Hero visual
- support diagram / mock
- Entry Report teaser
- optional minor support

スクロールギャラリー化しない。

### 4-12. 背景モチーフの固定
背景には、必要な場合に限り、ごく薄い grid / blueprint line / geometric guide を使ってよい。  
ただし、意味のないSF演出やネオンUIにはしない。  
目的は「設計図のような精密さ」の補助であり、視線を奪う主役化ではない。

## 5. 5つの解析軸ビジュアルSSOT（Hard Freeze）

### 5-1. 5軸の正式表記
- C = Create / 創造・成長
- E = Express / 表現・情熱
- S = Support / 共鳴・育成
- D = Decide / 判断・洗練
- L = Logic / 知性・流動

### 5-2. 公開面での表示ルール
- Home の主表示は C / E / S / D / L と日本語補助語を優先する
- 木 / 火 / 土 / 金 / 水 は公開Heroや主要導線の主説明にしない
- 木 / 火 / 土 / 金 / 水 は内部ロジックまたは補助辞書としてのみ扱ってよい
- 公開面で「五行」を主概念にしない

### 5-3. 必須要素
- donut / ring chart
- 軸略号（C / E / S / D / L）
- 軸正式名
- 日本語補助語
- 数値表示
- 短い但し書き

### 5-4. 数値表示の固定ルール
数値は表示してよい。むしろ固定表示を推奨する。  
ただし、これは他人との優劣ではなく「自分の中の配分」を見るための数値として扱う。

固定ルール:
- 5軸合計 = 100
- 各軸は合計100の中での構成比として表示する
- 表示値は整数パーセント（例: 24 / 21 / 18 / 17 / 20）
- 文言は「スコア」ではなく「比率」「配分」「バランス」を優先
- 順位表示、偏差値表示、他ユーザー比較表示はしない
- 「高いほど良い」と読める色運用は禁止

### 5-5. 円グラフの意味定義
この円グラフは能力順位ではない。  
この円グラフは「その人の中で、どの性質にエネルギーが配分されやすいか」を見せるための見取り図である。

固定補助文:
「5つの解析軸の見方」  
「C〜L のバランスで傾向を整理」  
「これは優劣ではなく、あなたの中の配分です。」

### 5-6. 円グラフのUI固定
- 左: donut chart
- 右: 5軸リスト
- 各行に 色点 / 略号 / 英語名 / 日本語補助語 / 数値 を置く
- 数値は `24%` のように直接表示してよい
- 数値の右に小さな square meter を置いてもよいが、数値を主、メーターを補助とする
- 凡例の並び順は C → E → S → D → L で固定

### 5-7. Free / Paid での扱い
- Home preview: donut + 5軸名 + 短い補助文まで
- Free report: donut + 数値 + 第1章 + 第2章
- Paid Entry Report: 同じ donut を冒頭に再掲してよい。以後の章ではこの配分を根拠に読解を進める

### 5-8. 色運用の固定
各軸は常に同じ色を使う。  
色の役割は意味識別であり、優劣印象の誘導ではない。  
よって、赤 = 危険、緑 = 正解のような評価意味を乗せない。

## 7. Entry Report 8章構成（Hard Freeze）

### 第1章 あなたという人物
役割: 全体結論。  
ユーザーに「私は何者なのか」の一次回答を返す。

### 第2章 構成と傾向の全体像
役割: 資質の配分・比重・偏りを整理する。  
順位づけではなく、構成の見方を渡す。

### 第3章 強みが自然に出る場面
役割: 努力しなくても出やすい力、反応、活きやすい場面を示す。

### 第4章 つまずきやすい偏り
役割: ネガティブに感じていた部分を、構造と配置の違いとして再解釈する。

### 第5章 本質と安定の条件
役割: ぶれにくくなる条件、力が安定する条件を示す。

### 第6章 役割・仕事との噛み合わせ
役割: この自分がどんな役割で活きやすいかを整理する。  
適職断定ではなく、噛み合わせの見方を渡す。

### 第7章 今の焦点と整え方
役割: いま何から整えるべきか、どこに意識を向けるとよいかを示す。

### 第8章 これからの使い方
役割: レポートを読み物で終わらせず、運用に変える。  
明日からどう使うかを短く具体的に渡す。

## 9. Free / Paid レポート境界線SSOT（Hard Freeze）

### 9-3. Free の文字数設計（最終 authority）

- Free の可変本文 target は **650〜900字**
- hard ceiling は **1,200字相当**
- Free は第1章 + 第2章 + donut + bridge で止め、Paid の代用品になる長文化をしない

出さないもの:

### 9-5. Paid Entry Report の固定構成

### 9-6. Paid の文字数設計（最終 authority）

- Paid の **可変本文 target は 2,800〜3,600字** とする
- 推奨中心帯は **3,000〜3,300字**

Paid の役割は「構造化」と「運用解」を渡すこと。  
第3章〜第8章で、強みの出し方、つまずきの再解釈、安定条件、役割との噛み合わせ、今の焦点、これからの使い方まで完遂する。

### 9-8. 価格以上感の作り方

- practical line

- donut + 数値 + 軸表
- 相談前提の問い
- owned artifact としての静かな完成感

「ただ長い」ではなく「多層で整理されている」感覚を作る。

- 相談で深める質問
- action box
- 固定補助モジュール

## 14. 凍結一文（最終）

M55の心は、ユーザーの潜在能力と偏りを見取り図として可視化し、否定していた自分を再解釈させ、前へ進むための使い方まで渡すことにある。  
したがって、今後のコピー・ビジュアル・構成はすべて、「自己理解」ではなく「自己再解釈と自己運用」を中心に統一する。  
また、商品設計は **単一ヒーロー商品を最も強く売る** ことを目的とし、Free では輪郭まで、Entry Report では意味・運用・再読価値までを明確に渡す。
