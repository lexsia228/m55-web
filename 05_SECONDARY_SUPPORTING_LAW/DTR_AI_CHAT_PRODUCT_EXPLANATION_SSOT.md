# M55 Web DTR × AI Chat Product Explanation SSOT

Status: DRAFT FOR FREEZE
Mode: product explanation / usage law
Scope: release-night MVP, Wave A monetization clarity, future chat refill integration

---

## 1. Objective

M55's first paid offer must be easy to understand.
The user must understand:
- what DTR is
- what the included AI chat is for
- how to use the DTR and the chat together
- what happens when the included chat is consumed
- where replenishment appears if refill is later enabled

This SSOT defines explanation law and product understanding law.
It does not change current price or route order.

---

## 2. Current release product law

Current first public paid lane:
- one-time `¥1,000 DTR`
- includes `AI chat 1 use / 1 consultation slot` as the first minimal consult layer

The product must be explained as:
- a personal report / reading artifact
- followed by one lightweight consult opportunity tied to that artifact

It must **not** be explained as an open-ended unlimited chatbot.

---

## 3. What the user must understand before purchase

The product page must make all of the following clear:

1. **What is delivered**
   - one DTR report
   - one included AI consult slot attached to that report

2. **How to use it**
   - first read the DTR
   - then ask the AI about points you want clarified
   - use the consult while viewing or after viewing the report

3. **What the AI chat is for**
   - clarification
   - interpretation follow-up
   - focused questions about the purchased DTR

4. **What the AI chat is not**
   - not a generic public chat toy
   - not unlimited by default
   - not detached from the purchased artifact

5. **What happens when the included use is consumed**
   - remaining count reaches zero
   - if refill is enabled, a refill CTA appears
   - if refill is not enabled yet, the UI explains that additional consult uses are not currently available

---

## 4. Mandatory product explanation blocks

The DTR product page must communicate these blocks in plain order:

1. What this product is
2. What is included now
3. How to use it step-by-step
4. Where it appears after purchase
5. What happens to the included AI consult count
6. Trust/support/legal references

---

## 5. Recommended explanation structure

### Block A: Product identity
- one calm title
- one short description

### Block B: Included items
Must explicitly enumerate:
- DTR report × 1
- AI consult use × 1

### Block C: How to use
Recommended 3-step explanation:
1. purchase
2. read your DTR
3. use the included AI consult to ask about the report

### Block D: Access after purchase
Explain where the user can go:
- success page
- My Page / purchased report area
- the report itself

### Block E: AI consult count
Explain that:
- included uses are visible
- remaining count is shown in the DTR/chat surface
- when count becomes zero, refill entry appears if enabled

---

## 6. Tone law

Allowed tone:
- precise
- premium
- explanatory
- calm
- product-oriented

Disallowed tone:
- mystical hype
- vague “ask anything forever” wording
- bait language
- hidden conditions

---

## 7. Remaining count visibility law

The remaining AI consult count must be visible at all times in any DTR-linked chat surface.

Minimum requirement:
- show current remaining count near the consult entry area
- show zero-state clearly when exhausted
- do not make the user guess whether consult usage remains

Recommended visible formats:
- 「残り 1 回」
- 「残り 0 回」

Do not hide count inside a secondary settings page.

---

## 8. Refill / top-up law

Refill may be added later, but the law is fixed now.

When remaining count reaches zero:
- a clear but calm refill CTA may appear
- the CTA must state what is being replenished
- the CTA must stay tied to the purchased DTR context

Allowed labels:
- 「相談回数を追加」
- 「相談を追加する」
- 「追加相談を購入」

Disallowed labels:
- generic “upgrade now” with unclear meaning
- hidden refill flow

If refill is not yet live:
- zero-state must still explain that included usage is exhausted
- support / future availability may be referenced, but do not fake availability

---

## 9. Use-case law

Allowed primary use cases:
- “I read the DTR and want one point clarified.”
- “I want help understanding a sentence or theme in the report.”
- “I want a focused follow-up after reading the report.”

Disallowed positioning:
- “talk endlessly with the AI”
- “replace the report with chat”
- “generic daily AI companion”

---

## 10. Surface placement law

### DTR product page
Must explain inclusion and usage.

### Success page
Must remind the user that the report is available and the included consult exists.

### My Page / purchased report area
Must show:
- owned DTR
- consult entry if available
- remaining count if applicable

### DTR reading view
If consult entry exists, it should feel adjacent to the report, not detached from it.

## 12. Do-not-do list

- do not hide that the consult use is limited
- do not separate consult from the DTR context
- do not position refill before the user understands the first included use

`¥1,000 DTR × AI chat 1 use` must be understood as:
- one paid report

- visible remaining count
